## 一、项目概述

NinjaTag 是校内线下追逐淘汰活动。每人有一个目标，形成全局单向环。淘汰目标后继承目标的目标，直到只剩一人。活动为期 5 天，参与者按学院分为四个阵营。每次有效击杀，击杀者阵营 +1 分。

技术栈：
- 前端：纯 HTML + CSS + JS（ES Module）
- 后端：Supabase（PostgreSQL + Auth + Storage）
- 部署：静态站点，本地用 python3 -m http.server 8080

- 发送登录邮件

## 五、运行逻辑

### 1. 事件生命周期
draft（未开始）→ active（进行中）↔ paused（暂停）→ ended（已结束）

- 开始活动：admin_start_event，重置所有人状态为 alive，生成代码，随机生成环，学院分归零，状态改为 active
- 暂停：admin_pause_event，状态改为 paused，击杀被拒
- 继续：admin_resume_event，状态改为 active
- 结束：admin_end_event('结束活动')，状态改为 ended
- 重新打乱：admin_reshuffle_alive，只对存活者重新生成环

### 2. 登录流程
1. 输入学校邮箱
2. 发送 Magic Link 或使用密码登录
3. 登录后判断：
   - 管理员 → admin.html
   - 已确认玩家 → me.html
   - 未确认玩家 → confirm.html

### 3. 身份确认
1. 根据邮箱查 participants
2. 显示姓名、照片、学院
3. "这是我" → confirm_identity() → me.html
4. "这不是我" → report_identity_issue() → 退出登录

### 4. 击杀流程
1. 猎人点击击杀当前目标
2. 输入目标本人的代码
3. 服务端事务：
   - 校验事件 active
   - 锁定猎人和目标
   - 校验猎人存活
   - 校验目标存活且是猎人当前目标
   - 校验输入代码等于目标本人的代码
   - 标记目标淘汰
   - 猎人继承目标的目标
   - 猎人学院 +1
   - 写击杀记录
   - 胜利判定
4. 返回结果

### 5. 胜利判定
- 只剩 1 人存活 → 猎人获胜，事件结束
- 猎人新目标是自己 → 猎人获胜，事件结束
- 获胜者 current_target_id 置为 null

### 6. 撤销击杀
- 只允许撤销最近一次有效击杀
- 恢复被淘汰者
- 恢复猎人目标
- 扣学院分
- 标记 status = revoked

### 7. 举报流程
- 玩家提交 → 进 reports 表
- 管理员查看（可见举报人）
- 处理：resolved / rejected
- 不可删除
