一、实现目的
================================================================

NinjaTag 是一个校内线下追逐淘汰活动系统，为期 5 天。
参与者按学院分为四个阵营：Red、Yellow、Blue、Green。
每人有一个“当前目标”，所有存活者构成一个全局单向环。
淘汰目标后，猎人继承目标的目标，直到只剩 1 人。
玩家击杀时需要输入目标本人的 6 位代码。
管理员可在全局链中直接执行击杀，并选择是否给对应学院加分。
系统提供公共主页、个人页、身份确认、管理后台，支持移动端访问。

三、表的内容和关系
================================================================

1. colleges（学院表，兼阵营）
   字段：
   - id uuid 主键
   - name text 学院名，唯一
   - color_hex text 颜色
   - score integer 学院分（=阵营分）
   - created_at timestamptz
   - updated_at timestamptz
   初始数据：Red、Yellow、Blue、Green

2. events（事件表）
   字段：
   - id uuid 主键
   - name text 事件名
   - status text draft / active / paused / ended
   - start_at timestamptz
   - end_at timestamptz
   - current_day integer 1-5
   - created_at timestamptz
   - updated_at timestamptz

3. participants（参与者表）
   字段：
   - id uuid 主键
   - event_id uuid → events.id
   - email text 学校邮箱，唯一
   - name text 姓名
   - photo_url text 照片
   - college_id uuid → colleges.id
   - code text 唯一代码（6位，排除 O0I1L）
   - status text alive / eliminated / winner
   - current_target_id uuid → participants.id
   - eliminated_by_id uuid → participants.id
   - eliminated_at timestamptz
   - is_confirmed boolean
   - confirmed_at timestamptz
   - created_at timestamptz
   - updated_at timestamptz
   约束：email 唯一、code 唯一、current_target_id <> id

4. eliminations（击杀记录表）
   字段：
   - id uuid 主键
   - event_id uuid → events.id
   - hunter_id uuid → participants.id
   - target_id uuid → participants.id
   - hunter_college_id uuid → colleges.id
   - target_college_id uuid → colleges.id
   - input_code text 输入的代码（管理员击杀为 'ADMIN'）
   - points_awarded integer 固定 1 或 0
   - status text valid / revoked
   - created_at timestamptz
   - revoked_at timestamptz
   - revoked_by uuid → admins.id
   - revoke_reason text

5. reports（举报表）
   字段：
   - id uuid 主键
   - event_id uuid → events.id
   - reporter_id uuid → participants.id
   - target_id uuid → participants.id
   - reason text
   - description text
   - evidence_url text
   - status text pending / resolved / rejected
   - admin_note text
   - handled_by uuid → admins.id
   - handled_at timestamptz
   - created_at timestamptz

6. daily_rules（每日规则表）
   字段：
   - id uuid 主键
   - event_id uuid → events.id
   - day_number integer 1-5
   - date date
   - title text
   - content text
   - published boolean
   - created_by uuid → admins.id
   - created_at timestamptz
   - updated_at timestamptz
   唯一约束：event_id + day_number

7. admins（管理员表）
   字段：
   - id uuid 主键
   - email text 管理员邮箱，唯一
   - name text 姓名
   - created_at timestamptz
   - updated_at timestamptz

表关系：
- colleges 1:N participants
- events 1:N participants
- events 1:N eliminations
- events 1:N reports
- events 1:N daily_rules
- participants 自关联：current_target_id、eliminated_by_id
- eliminations N:1 participants（hunter）
- eliminations N:1 participants（target）
- eliminations N:1 colleges（hunter_college、target_college）
- eliminations N:1 admins（revoked_by）
- reports N:1 participants（reporter、target）
- reports N:1 admins（handled_by）
- daily_rules N:1 admins（created_by）

视图：
- public_home_view：公共主页数据
- public_alive_wall_view：存活墙

五、Role 的划分
================================================================

1. 未登录访客
   - 可访问：公共主页
   - 可见：事件状态、阵营分、存活墙、人数、今日规则、赢家
   - 不可见：任何人的目标信息、代码
   - 不可操作：击杀、举报、进入个人页

2. 玩家（已登录且已确认）
   - 可访问：个人页
   - 可见：自己的代码、当前目标、已淘汰的人、自己的状态
   - 可操作：击杀、举报
   - 不可见：他人目标、他人代码
   - 不可修改：个人资料、学院、阵营、代码、分数、规则

3. 管理员
   - 可访问：全部页面
   - 可修改：所有数据
   - 可操作：导入、编辑、删除参与者、上传照片、设置学院、生成代码和环、
     开始/暂停/继续/结束活动、发布规则、处理举报、撤销击杀、加减分、
     重置分、导出数据、全局链中击杀、生成/删除测试角色、查看全局链（含排序和搜索）

4. 系统
   - 发送登录邮件
   - 生成唯一代码
   - 生成随机环
   - 校验击杀代码
   - 事务更新环、状态、分数
   - 胜利判定
   - 全局链排序与搜索

5. RLS 策略
   - colleges：匿名可读，管理员可写
   - events：匿名可读，管理员可写
   - daily_rules：匿名只能读已发布，管理员可写
   - participants：玩家只能读自己，管理员全读全写
   - admins：仅管理员可读
   - eliminations：玩家只能读自己作为猎人的记录，管理员全读全写
   - reports：玩家可 insert，管理员可读可更新，不可删除

6. Storage 策略
   - photos：匿名可读，管理员可写
   - evidence：玩家可上传，仅管理员可读
