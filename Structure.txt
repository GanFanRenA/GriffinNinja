================================================================
NinjaTag 项目功能文档（截至 2026-10-11）
================================================================

本文件记录当前版本已实现的功能、数据表结构、表关系、
RPC 函数清单，以及角色与权限划分。

================================================================
一、已实现的功能
================================================================

【1. 登录与账号】
- 仅管理员可登录，参与者登录入口已关闭。
- 登录方式：
  - 学校邮箱 Magic Link（默认）
  - 测试用密码登录（保留用于开发调试）
- 登录后路由：
  - 管理员 → admin.html
  - 非管理员 → 提示"仅管理员可以登录"后强制退出到首页
- 学校邮箱域名限制：@bjsmicschool.com

【2. 公共主页（index.html）】
- 匿名可访问，展示：
  - 活动状态、当前天数
  - 阵营分数
  - 存活 / 淘汰人数
  - 今日规则
  - 存活墙
  - 最终赢家
- 数据每 5 秒轮询一次。
- 存活墙做了数据指纹，避免重复渲染。

【3. 首页板块可见性开关】
- 管理员登录首页时，每个板块标题右侧出现「公开可见」开关。
- 可控制板块是否对非管理员可见。
- 板块列表：
  - event      活动状态
  - colleges   阵营分数
  - counts     人数
  - today_rule 今日规则
  - alive_wall 存活墙
  - winner     最终赢家
- 非管理员访问时按配置隐藏板块。

【4. 管理后台（admin.html）】
包含 Tab：
- 事件
- 学院
- 参与者
- 每日规则
- 全局链
- 击杀记录
- 历史记录
- 管理员

已隐藏 Tab（入口关闭，代码保留）：
- 举报

【5. 事件管理】
- 开始活动：重置所有参与者为 alive、生成新代码、随机生成环、学院分归零
- 重新打乱存活者：只对存活者重新生成环
- 暂停 / 继续
- 结束活动（需输入"结束活动"确认）
- 修改事件名称与当前天数

【6. 学院管理】
- 编辑学院名称与颜色
- 单个学院手动 +1 / -1 分
- 展示每个学院的人数

【7. 参与者管理】
- 添加单个参与者
  - 必填：name
  - 可选：grade、house（college）、photo_url、email
  - 邮箱若填写，需为学校邮箱且唯一
- CSV 批量导入
  - 列顺序：name, grade, house, photo_url, email
  - 姓名为空的行跳过
  - 邮箱重复的行跳过
- 编辑参与者
  - 可修改：name、grade、house、photo_url、email
  - 邮箱仍需校验域名与唯一性
- 删除参与者
  - 同步清理其击杀记录、举报、相关引用
- 搜索：按姓名 / 邮箱 / grade 过滤

【8. Grade 枚举】
固定为：G9、G10、G11、G12、Teacher
- 单个添加：下拉选择
- CSV 导入：文本，非法值视为空
- 数据库可选加 CHECK 约束兜底

【9. 每日规则】
- 按 Day 1-5 发布
- 标题 + 内容
- 已发布规则可编辑

【10. 全局链】
- 展示所有参与者的代码、目标、目标代码、状态
- 搜索：姓名 / 代码 / 目标姓名 / 目标代码
- 对存活且有目标的参与者提供「完成击杀」按钮

【11. 击杀原因细化】
点击「完成击杀」后弹出原因选择 Modal：
- 正常击杀        → 得分
- 违反规则        → 得分
- 未完成任务      → 得分
- 缺勤            → 得分
- 不计分击杀      → 不得分

选择后弹出二次确认：
「确定"目标名"因为"原因"而被击杀，"HunterHouse"将（不）得分。」

确认后调 admin_kill_target 执行击杀：
- 目标标记 eliminated
- 猎人继承目标
- 若原因计分，猎人学院 +1
- 写 eliminations（含 reason）
- 写审计日志
- 判断胜利

【12. 重新加入已淘汰者】
- 在全局链 Tab 下方：
  - 搜索已淘汰者（姓名 / 邮箱）
  - 选择要插入的位置：Hunter 名 → 目标名
  - 语义：Hunter → 新加入者 → 原目标
- 重新加入后：
  - 状态恢复为 alive
  - 清空 eliminated_by_id / eliminated_at
  - 生成新的 6 位唯一代码
  - current_target_id 设为 Hunter 的原目标
  - Hunter 的 current_target_id 设为新加入者

【13. 击杀记录】
- 展示所有击杀：猎人 → 目标、双方学院、时间、状态
- 可撤销最近的有效击杀：
  - 恢复被淘汰者
  - 恢复猎人目标
  - 按 points_awarded 扣学院分
  - 标记 status = revoked

【14. 历史记录】
- 合并三类事件，按时间倒序：
  - 击杀（valid eliminations）
  - 撤销（revoked eliminations）
  - 复活（audit_logs 中 reinsert_participant）
- 每条记录包含：
  - 击杀：谁杀了谁、什么时候、哪个学院得分、原因、是否管理员击杀
  - 撤销：撤销了哪次击杀、什么时候、哪个学院减分、原因、操作者
  - 复活：复活了谁、什么时候、插入到谁之后、操作者
- 支持搜索：姓名、学院、原因、操作者

【15. 管理员管理】
- 查看管理员列表
- 添加管理员（邮箱 + 姓名）
- 移除管理员
  - 不能移除自己
  - 至少保留一名管理员
  - 确认文案：「是否确认将'Name'的管理员职责移除？」

【16. 审计日志（后端已有，前端未接入）】
- 记录管理员关键操作
- 支持查看、删除单条、清空所有

================================================================
二、数据表结构
================================================================

【1. colleges（学院 / 阵营）】
- id                uuid 主键
- name              text 唯一
- color_hex         text 颜色
- score             integer 学院分
- created_at        timestamptz
- updated_at        timestamptz
初始数据：Red、Yellow、Blue、Green

【2. events（事件）】
- id                uuid 主键
- name              text
- status            text  draft / active / paused / ended
- start_at          timestamptz
- end_at            timestamptz
- current_day       integer 1-5
- created_at        timestamptz
- updated_at        timestamptz

【3. participants（参与者）】
- id                uuid 主键
- event_id          uuid → events.id
- email             text 可空，唯一（多个 NULL 不冲突）
- name              text 必填
- grade             text 可空（G9/G10/G11/G12/Teacher）
- photo_url         text 可空
- college_id        uuid → colleges.id，可空
- code              text 唯一，6 位（排除 O0I1L）
- status            text alive / eliminated / winner
- current_target_id uuid → participants.id
- eliminated_by_id  uuid → participants.id
- eliminated_at     timestamptz
- is_confirmed      boolean
- confirmed_at      timestamptz
- created_at        timestamptz
- updated_at        timestamptz
约束：
- email 唯一（NULL 除外）
- code 唯一
- current_target_id <> id

【4. eliminations（击杀记录）】
- id                 uuid 主键
- event_id           uuid → events.id
- hunter_id          uuid → participants.id
- target_id          uuid → participants.id
- hunter_college_id  uuid → colleges.id
- target_college_id  uuid → colleges.id
- input_code         text  'ADMIN' 表示管理员击杀
- points_awarded     integer 1 或 0
- reason             text 击杀原因
                        normal / rule_violation /
                        task_incomplete / absent / no_points
- status             text  valid / revoked
- created_at         timestamptz
- revoked_at         timestamptz
- revoked_by         uuid → admins.id
- revoke_reason      text

【5. reports（举报）】
- id              uuid 主键
- event_id        uuid → events.id
- reporter_id     uuid → participants.id
- target_id       uuid → participants.id
- reason          text
- description     text
- evidence_url    text
- status          text  pending / resolved / rejected
- admin_note      text
- handled_by      uuid → admins.id
- handled_at      timestamptz
- created_at      timestamptz
备注：前端入口已关闭，表和数据保留。

【6. daily_rules（每日规则）】
- id              uuid 主键
- event_id        uuid → events.id
- day_number      integer 1-5
- date            date
- title           text
- content         text
- published       boolean
- created_by      uuid → admins.id
- created_at      timestamptz
- updated_at      timestamptz
唯一约束：event_id + day_number

【7. admins（管理员）】
- id              uuid 主键
- email           text 唯一
- name            text
- created_at      timestamptz
- updated_at      timestamptz

【8. audit_logs（审计日志）】
- id              uuid 主键
- event_id        uuid → events.id ON DELETE SET NULL
- admin_id        uuid → admins.id ON DELETE SET NULL
- admin_email     text
- action          text NOT NULL
- details         jsonb DEFAULT '{}'::jsonb
- created_at      timestamptz DEFAULT now()
索引：event_id、created_at DESC

【9. home_sections（首页板块可见性）】
- key                text 主键
- label              text
- visible_to_public  boolean DEFAULT true
- sort_order         integer
- updated_at         timestamptz
初始数据：
- event      活动状态
- colleges   阵营分数
- counts     人数
- today_rule 今日规则
- alive_wall 存活墙
- winner     最终赢家

================================================================
三、表的关系
================================================================

- colleges 1:N participants          （一个学院多个参与者）
- colleges 1:N eliminations          （hunter_college_id / target_college_id）
- events    1:N participants
- events    1:N eliminations
- events    1:N reports
- events    1:N daily_rules
- events    1:N audit_logs

- participants 自关联：
  - current_target_id → participants.id
  - eliminated_by_id  → participants.id

- eliminations N:1 participants（hunter_id）
- eliminations N:1 participants（target_id）
- eliminations N:1 admins（revoked_by）

- reports N:1 participants（reporter_id）
- reports N:1 participants（target_id）
- reports N:1 admins（handled_by）

- daily_rules N:1 admins（created_by）

- audit_logs N:1 admins（admin_id）

- home_sections 独立表，不与其它表关联

四、SQL 函数清单（RPC）
================================================================

【公共 / 通用】
- get_public_home()
    公共主页数据：事件、阵营分、人数、今日规则、存活墙、赢家
- get_home_section_visibility()
    返回 { key: visible_to_public } 映射
- is_admin()
    判断当前登录用户是否在 admins 表中
- current_user_email()
    返回当前登录用户的邮箱
- is_school_email(p_email)
    判断是否为学校邮箱

【玩家侧（玩家登录已关闭，函数保留）】
- get_my_profile()
- confirm_identity()
- report_identity_issue(text)
- kill_target(uuid, text)
- submit_report(uuid, text, text, text)

【事件管理】
- admin_get_event()
- admin_update_event(p_name, p_current_day)
- admin_start_event()
    重置参与者、生成代码、生成环、清空击杀记录、写审计日志
- admin_reshuffle_alive()
    只对存活者重新生成环
- admin_pause_event()
- admin_resume_event()
- admin_end_event(p_confirm text)

【学院管理】
- admin_get_colleges()
- admin_update_college(p_id, p_name, p_color)
- admin_adjust_college_score(p_college_id, p_delta)
- admin_reset_college_scores()

【参与者管理】
- admin_get_participants()
    返回 id、name、grade、email、photo_url、
    college_id、college_name、status、code
- admin_add_participant(p_name, p_grade, p_college_id,
                       p_photo_url, p_email)
- admin_update_participant(p_id, p_name, p_grade,
                          p_college_id, p_photo_url, p_email)
- admin_delete_participant(p_id)
    同步清理击杀记录、举报、相关引用
- admin_import_participants(p_rows jsonb)
    CSV 批量导入

【每日规则】
- admin_get_daily_rules()
- admin_publish_daily_rule(p_day, p_title, p_content)

【全局链与击杀】
- admin_get_global_chain()
    返回每位参与者的 name、code、status、
    target_name、target_code、college_name
- admin_kill_target(p_hunter_id uuid, p_reason text)
    管理员击杀：
    - reason 决定是否加分
    - 写 eliminations（含 reason）
    - 写审计日志
    - 判断胜利
- admin_revoke_kill(p_elimination_id, p_reason)
    撤销击杀：
    - 恢复被淘汰者
    - 恢复猎人目标
    - 扣学院分
    - 标记 status = revoked
    - 记录 revoked_at、revoked_by、revoke_reason

【重新加入已淘汰者】
- admin_search_eliminated_participants(p_query text)
    搜索已淘汰者，返回 id、name、grade、email、
    college_name、color、eliminated_at
- admin_reinsert_participant(p_participant_id, p_hunter_id)
    插入到 Hunter → 原目标 之间：
    - 恢复 alive
    - 生成新代码
    - 继承 Hunter 的原目标
    - Hunter 目标指向新加入者
    - 写审计日志

【历史记录】
- admin_get_history(p_limit integer)
    合并三类事件：
    - kill     （valid eliminations）
    - revoke   （revoked eliminations）
    - reinsert （audit_logs 中 reinsert_participant）
    按时间倒序返回

【首页板块可见性】
- admin_get_home_sections()
    管理员读取所有板块及可见性
- admin_set_home_section_visibility(p_key, p_visible)
    切换某板块的公开可见性

【管理员管理】
- admin_get_admins()
- admin_add_admin(p_email, p_name)
- admin_delete_admin(p_id)
    保护逻辑：
    - 不能删除自己（cannot_delete_self）
    - 至少保留一名管理员（must_keep_one_admin）

【举报（前端入口已关闭，函数保留）】
- admin_get_reports()
- admin_handle_report(p_report_id, p_status, p_note)

【审计日志（后端已有，前端未接入）】
- admin_get_audit_logs()
- admin_delete_audit_log(p_log_id)
- admin_clear_audit_logs()

================================================================
五、角色与权限划分
================================================================

【1. 未登录访客】
可访问：
- index.html（公共主页）

可见：
- 活动状态、当前天数
- 阵营分数（若开关开启）
- 存活 / 淘汰人数（若开关开启）
- 今日规则（若开关开启）
- 存活墙（若开关开启）
- 最终赢家（若开关开启）

不可见：
- 任何人的目标信息、代码
- 个人页、后台

不可操作：
- 击杀、举报、登录

【2. 玩家（已登录且已确认）】
状态：当前版本已关闭登录入口，此角色暂不使用。
函数与页面保留：
- me.html、confirm.html
- kill_target、submit_report、get_my_profile
- confirm_identity、report_identity_issue

【3. 管理员】
可访问：
- index.html（含板块可见性开关）
- admin.html（全部 Tab）

可操作：
- 事件：开始 / 打乱 / 暂停 / 继续 / 结束 / 改名 / 改天数
- 学院：编辑 / 加减分 / 重置分
- 参与者：添加 / 导入 / 编辑 / 删除 / 搜索
- 每日规则：发布 / 编辑
- 全局链：搜索 / 完成击杀（含原因）/ 重新加入已淘汰者
- 击杀记录：查看 / 撤销
- 历史记录：查看 / 搜索
- 首页板块可见性：切换开关
- 管理员：查看 / 添加 / 移除

不可操作：
- 修改自己的管理员身份（不能移除自己）
- 移除最后一名管理员

【4. 系统】
- 发送登录邮件（Magic Link）
- 生成唯一 6 位代码（排除 O0I1L）
- 生成随机全局单向环
- 校验击杀代码
- 事务更新环、状态、学院分
- 写审计日志
- 判断胜利：
  - 只剩 1 人存活 → 该人获胜
  - 猎人新目标是自己 → 猎人获胜

================================================================
六、RLS 策略概览
================================================================

- colleges：匿名可读，管理员可写
- events：匿名可读，管理员可写
- daily_rules：匿名只读已发布，管理员可写
- participants：玩家只能读自己，管理员全读全写
- admins：仅管理员可读
- eliminations：玩家只能读自己作为猎人的记录，管理员全读全写
- reports：玩家可 insert，管理员可读可更新，不可删除
- audit_logs：仅管理员可读、可删除
- home_sections：匿名可读，管理员可写

================================================================ 十、国际化（i18n） ================================================================ - 新增 js/i18n.js：字典、t(key, params)、initI18n()、setLocale()、 applyI18n(root)、mountLanguageSwitcher(target)。 - HTML 静态文本通过 data-i18n / data-i18n-html / data-i18n-placeholder / data-i18n-title / data-i18n-aria-label 标注。 - JS 动态文本统一走 t('namespace.key', params)。 - 语言切换器挂载点： - 认证页 / 公共页：<div id="lang-switch"> 在 site-header 内 - 后台：sidebar-lang-switch（侧边栏底部） - drawer-lang-switch（移动端「更多」抽屉内） - 语言优先级：URL ?lang= > localStorage ninjatag.locale > navigator.language > 默认 zh-CN。 - 切换语言会派发 localechange 事件，各模块订阅后重绘： - public.js → loadPublicHome() - admin.js → refreshParticipantsI18n / refreshChainI18n / refreshRecordsI18n / refreshMiscI18n + 概览刷新 - 数据库内容（姓名、邮箱、学院名、活动名、规则内容）不参与 i18n。 - 首页板块开关名称通过 SECTION_LABEL_KEYS 映射到 i18n key，回退到 home_sections.label。
